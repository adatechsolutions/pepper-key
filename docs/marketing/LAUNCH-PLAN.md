# PepperKey launch and campaign plan

## Launch objective

Establish PepperKey as a transparent, carefully bounded USB U2F project from Ada Tech Solutions Inc., earn technically credible adoption through the Flipper Apps Catalog and GitHub, and generate qualified interest in compatibility/release-assurance services.

The launch is evidence-led: public source first, physical acceptance second, Catalog submission third, then promotion. Bluetooth remains a separately scoped research roadmap and is not a v0.1 launch claim.

## Audience

- Flipper Zero developers and enthusiasts.
- Security educators and lab operators.
- Developers maintaining legacy U2F integrations.
- Technical teams interested in evidence-backed embedded security workflows.

## Positioning

Core message: **A deliberately gated, open-source USB U2F application for Flipper Zero—built with explicit approval, fail-closed state handling, and honest limits.**

Proof points: locked-by-default UI, long-hold arming/approval, one-success lock, complete application-hash binding, exact-size encrypted records, fail-closed state recovery, terminal USB teardown, pinned build, public source, and published limitations.

## Launch sequence

### Phase 0 — release evidence

- Complete device/fault/recovery and disposable-account acceptance.
- Capture the genuine screen and a short redacted demo.
- Publish the AdaTech commit, CI result, FAP hash, security/remediation summary, compatibility matrix, and rollback instructions.
- Complete name/mark and GPL distribution review.

### Phase 1 — owned launch

- GitHub v0.1.0 pre-release/release with exact artifact receipt.
- AdaTech technical article: design goals, threat model, limits, and why Bluetooth is separate.
- AdaTech project page with Catalog/GitHub links and no credential collection.
- LinkedIn and X posts linking to the technical article.
- Short video showing locked, arm, register prompt, long-hold approval, success, and automatic lock using a disposable account.

### Phase 2 — community distribution

- Submit one-app Flipper Apps Catalog PR.
- Share a technical, non-promotional write-up only where community rules permit.
- Invite compatibility reports through the structured GitHub template.
- Offer a maintainer Q&A focused on U2F boundaries and recovery safety.

### Phase 3 — measured paid tests

Start only after Catalog acceptance and a written budget/owner approval.

- Google Search: exact/phrase intent around Flipper U2F app and USB security-key experimentation.
- Reddit: tightly scoped developer/security interests, with community-policy review and comments monitored.
- LinkedIn: small technical-leadership test for lab/training and compatibility-assessment services.

Do not run broad consumer, fear-based security, passkey, certification, or competitor-conquest campaigns.

## Six-week editorial calendar

1. Week 1: source/review story and release receipt.
2. Week 2: threat-model deep dive and recovery checklist.
3. Week 3: device demo and compatibility matrix.
4. Week 4: “U2F vs CTAP2/passkeys” limits explainer.
5. Week 5: pinned embedded release workflow and artifact-binding case study.
6. Week 6: compatibility findings, roadmap decision, and support offer.

## Funnel and measurement

- Awareness: qualified article/video views and Catalog listing views.
- Engagement: README-to-install clicks, documentation depth, and demo completion.
- Adoption: Catalog installs, GitHub release downloads, successful compatibility reports.
- Quality: crash/error rate, invalid-state reports, recovery-test completion, median triage time.
- Commercial: qualified assessment inquiries, scoped proposals, wins, delivery margin, and support renewal.

Exclude bots, internal traffic, and unverified installation counts. Do not collect credential/device identifiers. Set campaign stop conditions for misleading-query share, unsafe support patterns, unresolved security issues, negative compatibility evidence, or cost above the approved threshold.

## Required assets

- 10×10 app icon and genuine 512×256 Catalog screenshot.
- Product page hero showing a real accepted device state.
- 30–45 second redacted demo and captioned cut-downs.
- Architecture/security diagram with USB-only boundary.
- Compatibility matrix, release receipt, recovery checklist, FAQ, and disclosure link.
- AdaTech-branded social cards with the USB-only and not-certified qualifiers visible.

No image may imply NFC/Bluetooth, passkeys, certification, or a named vendor comparison.
